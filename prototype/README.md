# 做T决策台 · 可运行原型 v0.1

> 单票 · 无券商通道 · 半自动 · L1 免费数据
> 目的：验证「特征 → regime → 信号 → 决策卡片 → 台账」这条链路，不是成品。

![决策台](shot_signals.png)

## 这是什么

一个**能跑真实行情**的最小闭环：

- 拉取当日真实 1 分钟分时 + 120 根前复权日 K（腾讯 L1 公开接口）
- 计算均价、滚动 VWAP、偏离 z 值、量比、斜率、ATR、日内振幅
- 判定 regime（震荡 / 上行 / 下行 / 极端），带状态机去抖
- 生成正T / 倒T 候选，逐条给出"通过 / 否决 + 理由"
- 用下一分钟价撮合，计入佣金、印花税、过户费、滑点
- 输出决策卡片、信号流水、门槛压测、账务与手工回填

## 快速开始

```bash
# 1. 重新生成数据（需要联网，只用标准库）
python build_demo.py            # 默认 sh600519
```

## 今日实测（600519，2026-10-19）

| 口径 | 候选 | 执行 | 结果 |
|---|---|---|---|
| 严格 0.45% | 9 | 0 | ¥0 |
| 放宽 0.25% | 9 | 1 | **−¥719**（其中成本 ¥381） |

茅台当日日内偏离只有 0.1%–0.3%，覆盖不了 0.142% 的往返成本。系统的结论是**不做**——这正是产品要卖的东西：

> 大多数日子、大多数股票，不应该做 T。

## 关键设计决策

1. **先判 regime，再找买点。** 上行禁止倒T（防卖飞），下行禁止正T（防做套），极端行情全禁。
2. **成本是硬门槛。** 目标价差必须覆盖 0.142% 往返成本后仍有净利，否则否决。否决理由要展示给用户。
3. **不做"为了凑目标而拉高预期"。** 目标价 = 滚动 VWAP，空间不足就不做。
4. **LLM 不在环内。** 本原型没有任何 LLM 调用；复盘归因才是它的位置。
5. **无券商 = 台账靠回填。** 页面里的"手工回填"是形态演示，不是可用的下单通道。

## 数据与撮合假设（重要）

- 行情：腾讯 `web.ifzq.gtimg.cn` / `qt.gtimg.cn`，非官方接口，无 SLA，仅适合原型。
- 撮合：信号下一分钟收盘价成交，偏差超过 0.15% 视为未成交；不模拟排队与部分成交。
- 出场：目标价 / 止损价 / 14:55 收盘平T，按分钟收盘价判断。
- 这是**偏乐观**的撮合模型；真实滑点与未成交率会更高。
- 单日样本，不足以证明策略有效。至少需要 20 个交易日并行验证。

## 已知局限

- 只有单日、单票；没有跨日样本。
- 没有 L2，盘口类策略全部未实现（也不该实现）。
- 没有真实成交回报，台账未做 T 对配对与未闭环识别（P3）。
- 前端为单文件原型，没有工程化构建。
